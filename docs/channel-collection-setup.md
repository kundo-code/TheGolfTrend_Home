# 블로그·유튜브 "전체 글" 수집 설정 안내

홈페이지 "여행 이야기"에 블로그·유튜브 채널의 **모든 글·영상**을 노출하려면 아래 3가지를 한 번만 설정하면 됩니다.
설정 전에도 홈페이지는 정상 동작합니다(기존처럼 RSS 최신 글만 노출).

| 순서 | 할 일 | 걸리는 시간 |
|---|---|---|
| 1 | Supabase에 저장 테이블 만들기 | 2분 |
| 2 | 유튜브 API 키 발급 (유튜브 채널을 쓰는 경우) | 5분 |
| 3 | Cloudflare에 수집 서버(Worker) 만들기 | 5분 |
| 4 | 관리자 패널에서 수집 서버 주소 입력 → 전체 수집 | 1분 |

---

## 1. Supabase 저장 테이블 만들기

1. https://supabase.com 로그인 → 홈페이지 프로젝트 선택
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. 저장소의 `docs/sql/2026-10-07_channel_posts.sql` 내용을 전부 붙여 넣고 **Run**
4. "Success" 가 나오면 완료

> 방문자는 이 표를 읽기만 하고, 쓰기·삭제는 관리자(로그인한 사용자)만 할 수 있도록 권한이 설정됩니다.

## 2. 유튜브 API 키 발급 (무료)

유튜브 채널을 등록해 두었다면 필요합니다. (네이버 블로그만 쓰면 건너뛰어도 됩니다.)

1. https://console.cloud.google.com 접속 → 상단에서 **새 프로젝트** 만들기 (예: `golftrend`)
2. 왼쪽 메뉴 **API 및 서비스 → 라이브러리** → `YouTube Data API v3` 검색 → **사용**
3. **API 및 서비스 → 사용자 인증 정보** → **사용자 인증 정보 만들기 → API 키**
4. 만들어진 키의 **키 수정** → "API 제한사항"에서 **키 제한 → YouTube Data API v3** 만 선택 → 저장
5. 키 문자열(AIza…)을 복사해 둡니다. **이 키는 홈페이지 코드에 넣지 않고 3단계의 Worker에만 저장합니다.**

> 하루 무료 사용량(10,000)이면 영상 50개당 1을 쓰므로 수천 개 영상도 충분합니다.

## 3. Cloudflare 수집 서버(Worker) 만들기

기존에 쓰던 프록시 Worker(`falling-smoke-4022…`)는 **그대로 두고**, 새 Worker를 하나 만듭니다.

1. https://dash.cloudflare.com 로그인 → **Workers & Pages** → **Create** → **Create Worker**
2. 이름을 `golftrend-collector` 로 정하고 **Deploy**
3. **Edit code** → 기존 내용을 모두 지우고 저장소의 `docs/worker/collector-worker.js` 내용을 붙여 넣기 → **Deploy**
4. Worker 화면의 **Settings → Variables and Secrets → Add**
   - `YOUTUBE_API_KEY` — 유형 **Secret**, 값: 2단계에서 복사한 키
   - `ALLOWED_ORIGINS` — 유형 **Text**, 값: `https://kundo-code.github.io` (다른 사이트가 이 서버와 API 키를 쓰지 못하게 막음. 도메인을 추가하면 쉼표로 이어서 입력)
5. Worker 주소(예: `https://golftrend-collector.○○○.workers.dev`)를 복사

확인: 브라우저 주소창에 `https://golftrend-collector.○○○.workers.dev/?mode=ping` 을 열어 `{"ok":true,"youtube":true}` 가 보이면 정상입니다.
(`ALLOWED_ORIGINS`를 넣었다면 주소창에서 직접 열어도 정상 응답이 옵니다 — 막는 것은 다른 사이트의 화면에서 호출하는 경우입니다.)

## 4. 관리자 패널에서 연결 · 첫 수집

1. 홈페이지 관리자 패널 → **이미지** 탭 → "📡 블로그 · 유튜브 자동 수집 채널"
2. **수집 서버 주소** 칸에 3단계의 Worker 주소 입력 → **연결 확인** → "✓ 연결됨"
3. **⟳ 전체 다시 수집** → 채널의 모든 글·영상을 가져와 저장 (글이 많으면 1~2분)
4. 이후에는 관리자 패널을 열 때 마지막 수집이 12시간 지났으면 **새 글만** 자동으로 가져옵니다. 바로 가져오려면 🔄.

---

## 동작 방식 요약

- **홈 "여행 이야기"**: "⭐ 추천 고정" 글 → 최신 글 순으로 12장. 오른쪽 위 **전체 보기 (N) →** 에서 나머지를 봅니다.
- **전체 보기**: 전체 / 블로그 / 유튜브 탭, 지역(연결 상품 기준), 제목 검색, 12개씩 "더 보기"(스크롤하면 자동).
- **관리자 글 목록**: 채널마다 제목 검색, 필터(연결 상품 없는 글 / 추천 고정 / 숨긴 글 / 직접 추가한 글), 20개씩 페이지. 글마다 ☆ 추천 고정, 🙈 숨기기, 연결 상품(여러 개) 지정.
- **홈페이지 부담**: 방문자 브라우저는 수집하지 않고 저장된 목록만 읽습니다. 홈은 최신 60개(+추천 고정)만, 전체 보기는 12개씩 필요한 만큼만 불러옵니다. 저장하는 것은 제목·링크·썸네일 주소·날짜뿐입니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| "저장소 미설정"으로 표시됨 | 1단계 SQL을 실행했는지, 실행 후 관리자 패널을 새로고침했는지 |
| 연결 확인 실패 | Worker 주소 오타, Worker가 Deploy 되었는지, `ALLOWED_ORIGINS`에 홈페이지 주소가 정확한지 |
| 유튜브만 "RSS 최신 글"로 수집됨 | `YOUTUBE_API_KEY`가 Secret으로 저장되었는지, YouTube Data API v3를 "사용" 했는지 |
| 네이버 블로그가 "RSS 최신 글"로 수집됨 | 네이버가 내부 목록 주소를 바꾼 경우일 수 있습니다(공식 API가 없음). 채널 카드에 실패 사유가 표시됩니다. 그동안은 RSS 최신 글 + "글/영상 주소 직접 추가"로 운영할 수 있습니다. |
| 특정 글만 안 보임 | 관리자 글 목록에서 숨김 처리되었는지 확인, 또는 채널 카드의 "글/영상 주소 직접 추가" |

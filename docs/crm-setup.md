# 상담·예약 데이터 통합 — 설정 안내

관리자 패널 **상담·예약** 탭은 전화·카카오톡·문자 상담과 예약 명단을 한곳에 모아 상품별 문의·예약 성과, 시즌·리드타임, 인원 수요를 분석합니다.
기존 관리자 패널 안의 탭이며, 기능 코드(`assets/admin-crm.js`)는 이 탭을 열 때만 불러옵니다(홈페이지 방문자 속도에 영향 없음).

## 1. DB 준비 (한 번)
1. Supabase 대시보드 → **SQL Editor** → `docs/sql/2026-10-24_crm_core.sql` 내용을 붙여 넣고 **Run**.
2. 결과 맨 아래에 나오는 **관리자 목록**을 확인합니다. 처음 실행할 때 이미 존재하던 로그인 계정이 모두 관리자로 등록됩니다.
   관리자가 아닌 계정이 보이면 SQL 파일 맨 아래 안내대로 삭제하세요.
3. Supabase → **Authentication → Sign In / Providers**에서 **Allow new users to sign up**이 꺼져 있는지 확인하세요.
4. 관리자 패널 → 상담·예약 → **🔧 연결 점검**에서 모든 항목이 ✅인지 확인합니다.

SQL을 실행하기 전에도 홈페이지·상품 관리·AI 리드는 지금처럼 동작합니다.

## 2. 무엇이 바뀌나
| 항목 | 변경 |
|---|---|
| 기존 테이블(kundo_site_state·channel_posts) | 변경 없음 |
| kundo_leads(AI 리드) | 데이터·구조 변경 없음. 읽기·수정 권한만 "허용된 관리자"로 좁힘(홈페이지 상담 신청 저장은 그대로) |
| 상품 데이터 | 상품마다 보이지 않는 고유번호(`uid`) 한 칸 추가. 기존 값은 그대로 |
| 새 테이블 | `tgt_*` (상담·이력·예약·상태 이력·가져오기 기록·연결 승인·운영 조건·출발 그룹·행동 기록·접근 기록) — 모두 관리자 전용 |
| 저장소 | 예약 명단 원본 백업용 비공개 버킷 `tgt-booking-imports` |

## 3. 데이터 원칙
- 일시는 UTC(timestamptz)로 저장하고 관리자 화면에는 한국 시간으로 표시합니다. 출발일은 날짜(date)입니다.
- **최초 문의일**은 후속 상담·수정으로 바뀌지 않습니다(DB 트리거로 보호).
- **예약 확정일·최초 출발일**은 처음 기록된 값이 유지되고, 상태·출발일·인원 변경은 이력으로 남습니다.
- 같은 예약번호는 1건으로만 집계하고, 같은 엑셀 파일은 두 번 가져오지 않습니다.
- 기존 기록의 날짜를 추정해 채우지 않으며, 자료가 부족하면 "자료 부족"으로 표시합니다.

## 4. 운영 조건 · 출발 그룹 · 기획/운영 진단
- **📐 상품 운영 조건**: 상품별로 적용 기간·인원 구간, 최소 출발 인원, 단독 출발 최소 인원, 합류 가능 여부, 소인원 추가 요금, 차량·송영·핸들링 비용, 최대 수용 인원을 기록합니다.
  출처는 필수이고, 최종 확인일이 180일을 넘으면 "확인 필요"로 표시합니다.
- **2인 출발 표시 원칙**: 운영 조건에 최소 출발(또는 단독 출발) 2인 이하가 등록된 경우에만 "2인 출발 가능"으로 표시합니다.
  합류만 가능한 상품은 "2인은 합류 시 출발", 조건이 없는 상품은 "미확인"으로 표시하고, 가능하다고 추정하지 않습니다.
- **🚐 출발 그룹**: 같은 상품·같은 출발일 예약을 묶어 티타임·객실·차량·송영 확보를 체크합니다.
  기본 확보 시점(해외 60/30일 전, 국내 30/14일 전)이 지나면 경고합니다. 기준은 `assets/admin-crm.js`의 `SECURE_LEAD`에서 바꿀 수 있습니다.
- **💡 기획·운영 진단**: 기록된 상담·예약만으로 규칙 기반 진단을 하고, 모든 항목에 근거 숫자를 함께 보여 줍니다.
  진단 항목은 맞는 상품이 없는 수요, 전환이 낮은 상품, 일정·예산 불일치, 관심 증가, 2인·단체 수요, 확보가 필요한 출발, 신규 상품 후보입니다.
  자료가 부족하면 "판단 보류"로 표시합니다.

## 5. 홈페이지 방문 기록 · 백업
- **방문 기록(익명)**: 방문자가 AI 추천 결과를 보거나, 추천 상품 상세를 열거나, "이 상품으로 상담 신청"을 누르면 `tgt_site_events`에 기록됩니다.
  상품 상세 보기, 상담 신청 제출, 전화·카카오톡·블로그/유튜브/밴드 클릭도 함께 기록됩니다.
  - 브라우저 탭 단위 임의 번호만 쓰고, 이름·연락처 같은 개인정보는 담지 않습니다.
  - 관리자 로그인 중 사용한 것은 기록하지 않습니다.
  - 테이블이 없거나 저장에 실패해도 홈페이지 동작에는 영향이 없습니다.
  - 방문자는 쓰기만 할 수 있고 읽기는 관리자만 가능합니다.
- 통계 화면 맨 아래 **🖱️ 홈페이지 AI 추천·상품 반응**에서 추천 노출·상세 보기율·상담 신청 이동을 상품별로 봅니다. 관심 지표일 뿐 상담·예약 실적에는 포함하지 않습니다.
- **💾 백업 내보내기**(🔧 연결 점검 화면): `tgt_*` 테이블 전체를 JSON 파일 하나로 내려받습니다. 내보내기는 접근 기록에 남습니다.

## 6. AI 멀티 큐레이션(추천·판매 전략)
목표는 고객마다 가장 잘 맞는 여행을 찾아 주면서, 전체 상품의 판매 기회와 매출총이익을 함께 높이는 것입니다.

**추가 SQL(한 번)**: `docs/sql/2026-10-25_curation.sql`을 SQL Editor에서 실행합니다. 되돌리기는 `docs/sql/2026-10-25_curation_rollback.sql`입니다.
- `tgt_product_strategy`: 상품별 1인 예상 매출총이익·만족도를 담습니다. 관리자 전용이며 홈페이지에는 공개되지 않습니다.
- `tgt_recommend_exposure(30)`: 최근 30일 상품별 추천 노출 합계만 돌려주는 함수입니다. 개인정보와 세션 정보는 돌려주지 않습니다.
- 실행 전에도 추천은 동작합니다. 다만 노출 기반 기회 보정과 이익·만족도 입력은 실행 후부터 됩니다.

**홈페이지 추천 방식**
1. **조건 필터**: 예산·일정·출발 시기(추천 판매 시기)를 충족한 상품만 추천합니다. 충족 상품이 6개보다 적으면 "조건을 조금 넓힌 대안"을 무엇이 다른지와 함께 따로 보여 줍니다.
2. **점수**: 고객 적합도(가장 큰 비중)에 판매 전략 등급 가중치와 노출 기회 보정을 더합니다.
   - 판매 전략 등급: 핵심 +8%, 틈새는 적합도 80% 이상일 때 +4%
   - 노출 기회 보정: 최근 노출이 적었던 상품에 최대 +6%
   - 가중치·보정은 적합도가 충분한 상품에만 적용합니다.
3. **테마별 배치**: 가장 잘 맞는 여행 · 가성비와 이동 편의 · 풍경과 특별한 경험 · 골프 코스 다양성 · 장기 체류와 휴식 · 새로운 발견 순으로 채웁니다.
   - 같은 국가·권역은 최대 2개까지입니다.
   - 테마 근거는 상품에 등록된 값(판매가·라운드·일정·비행시간·상품 문구)만 씁니다.

**관리자 → 상담·예약 → 🎯 추천·판매 전략**
- 상품별 판매 전략 등급(핵심/일반/틈새)을 지정합니다. 상품 정보에 저장되어 홈페이지 추천에 바로 반영됩니다.
- 1인 예상 매출총이익과 만족도(근거 포함)를 입력합니다.
- 상품별로 추천 노출 → 상세 보기 → 상담 이동 → 상담 → 예약 확정 흐름과 예상 매출총이익을 봅니다.
- 진단 항목: 노출 쏠림(상위 3개 50% 초과), 기회 부족(30일 노출 0회), 국가 집중(90일 예약 50% 초과), 핵심 상품 과다. 자료가 부족하면 "판단 보류"로 표시합니다.

## 7. 홈페이지 방문 행동 · 경영 진단·제안
**추가 SQL(한 번)**: `docs/sql/2026-10-26_visitor_insights.sql`. 기록할 수 있는 행동 종류만 늘리며, 되돌리기는 `..._rollback.sql`입니다.

**상담 신청 개인정보 동의 기록(한 번)**: `docs/sql/2026-10-27_lead_consent.sql` — `kundo_leads`에 동의 일시·문구 버전·선택 동의 여부·접수번호 칸을 추가합니다(기존 데이터는 그대로). 실행 전에도 접수는 정상 동작하며, 이 경우 동의 기록은 "세부 요청" 끝에 문장으로 남습니다. 되돌리기는 `..._rollback.sql`(저장된 동의 기록도 함께 삭제되므로 먼저 백업).
새로 기록되는 행동은 모두 익명이고 관리자 로그인 중에는 기록하지 않습니다.
- 방문(탭당 1회): 유입 도메인, 모바일/PC, utm 광고 태그
- 국가·권역 카드 열기
- AI 추천 검색: 고른 조건, 조건 충족 상품 수, 상품이 빠진 이유
- 상담 신청서 작성 시작
- 상품 상세를 50%·90%까지 읽음
- 상세 페이지 안 전화·카카오 클릭: 어떤 상품에서 눌렀는지 함께 기록

**📊 통계 → 🖱️ 홈페이지 방문 행동**에서 보는 것:
- 방문 → 탐색 → 상세 → 상담 행동 → 신청 제출 단계별 흐름
- 최근 30일 일별 방문, 유입 경로·광고, 기기별 상담 비율, 행동 종류별 건수
- 고객이 고른 추천 조건(예산·일정·권역·출발 월·취향), 국가·권역 관심도 대비 판매 상품 수
- 상품별 반응(상세 조회·정독·추천 클릭률·상담 이동·전화/카톡)

**📊 통계 → 🧭 경영 진단·제안**: 방문 행동, 상담·예약 기록, 상품 정보를 함께 보고 규칙에 따라 제안합니다.
제안은 네 가지로 나눠 근거 숫자와 함께 보여 줍니다.
- 추가해야 할 상품
- 기존 상품 보완
- 조건·운영 보완
- 노출·전환 개선

자료가 부족하면 "판단 보류"로 표시합니다. 기준은 추천 검색 20회, 국가 카드 열기 20회, 상품 상세 10회, 기기별 방문 30회입니다.

**AI 추천 ⑥ 세부 조건(선택)**: 출발 공항, 항공 포함/별도, 항공 패턴(조조·조석·석석), 주말/평일 출발, 짧은 비행(3시간 이내), 골프장 가까운 숙소(30분 이내), 라운드 많이/여유롭게, 식사 포함, 프리미엄 등급, 실속·특가, 2인 출발을 고를 수 있습니다.
- 판단에는 상품 카드·요금표에 이미 등록된 값만 씁니다.
- 값이 없는 상품은 "미확인"으로 표시하고 일부 점수만 줍니다. 순서는 확인된 일치 > 미확인 > 확인된 불일치입니다.
- 경영 진단은 이 조건들의 수요를 보고, 맞는 상품이 적으면 "상품 보강", 판단할 정보가 비어 있으면 "정보 등록"을 제안합니다.
